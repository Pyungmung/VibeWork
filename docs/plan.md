# 같은 음식 이모지 찾기 게임 앱 기획서 프롬프트

## 1. 프로젝트 요청

HTML, CSS, JavaScript만 사용해 누구나 파일을 열어 바로 실행할 수 있는 간단한 웹게임을 만들어줘.
게임 이름은 **푸드 이모지 짝찾기**로 한다. 별도의 프레임워크, 빌드 도구, 서버, 외부 라이브러리 없이 구현하고, `index.html`, `style.css`, `script.js` 파일로 분리한다.

## 2. 게임 목표

8행 6열 격자에 음식 이모지를 무작위로 배치한다. 사용자는 같은 음식 이모지를 찾아 드래그하거나 손가락으로 터치해 두 개씩 선택한다. 같은 이모지 한 쌍을 맞히면 두 이모지가 보드에서 사라지고, 모든 이모지를 제거하면 게임을 클리어한다.

## 3. 보드와 음식 이모지 배치

- 게임 보드는 **8행 6열**, 총 48칸으로 구성한다.
- 약 20가지 음식 이모지를 사용한다. 예시 목록:
	`🍎`, `🍕`, `🍔`, `🍟`, `🌭`, `🍿`, `🍩`, `🍪`, `🍰`, `🍉`, `🍓`, `🍌`, `🍇`, `🍒`, `🥕`, `🌽`, `🍣`, `🍙`, `🍜`, `🍦`
- 음식 이모지 목록에서 필요한 종류를 무작위로 선택해 **24개의 짝**을 만든다.
- 전체 48개의 이모지는 항상 짝수 개로 구성하며, 각 이모지는 반드시 같은 이모지 하나와 짝을 이룬다.
- 약 20종의 이모지로 24쌍을 만들기 위해 일부 음식 이모지는 여러 쌍으로 등장할 수 있다.
- 완성된 48개 타일의 위치를 무작위로 섞어 8행 6열에 배치한다.
- 새로 시작할 때마다 음식 종류와 타일 위치가 달라지도록 한다.
- 이모지 자체가 잘 보이도록 충분한 크기의 타일과 여백을 사용한다.

## 4. 핵심 게임 규칙

- 사용자는 같은 음식 이모지 두 개를 선택해 한 쌍을 맞힌다.
- 마우스로 타일을 드래그하거나 클릭해 선택할 수 있어야 한다.
- 모바일에서는 손가락으로 터치하거나 드래그해 선택할 수 있어야 한다.
- 첫 번째 타일을 선택한 뒤 두 번째 타일을 선택하면 두 이모지를 비교한다.
- 두 이모지가 같으면 정답 처리하고, 해당 타일 두 개를 화면에서 사라지게 한다.
- 두 이모지가 다르면 오답 처리하고, 잠시 선택 상태를 보여준 뒤 다시 선택할 수 있도록 원래 상태로 되돌린다.
- 이미 맞혀서 사라진 타일은 다시 선택할 수 없게 한다.
- 한 번에 두 개를 초과해 선택하지 않도록 한다.
- 같은 타일을 두 번 선택한 경우에는 선택을 취소하고 다시 선택할 수 있게 한다.
- 정답으로 제거된 쌍의 수와 현재 시도 횟수 또는 점수를 화면에 표시한다.
- 기본 점수 규칙은 정답 한 쌍당 2점으로 하고, 오답에서는 점수를 차감하지 않는다.
- 모든 타일이 사라지면 게임 클리어 상태를 표시한다.

## 5. 드래그 및 터치 입력

- 마우스와 터치 입력을 모두 지원한다.
- 가능하면 `Pointer Events`를 사용해 입력 로직을 하나로 관리한다.
- 포인터가 첫 번째 타일 위에서 시작했을 때만 선택을 시작한다.
- 포인터를 두 번째 타일 위에서 놓으면 두 타일을 비교한다.
- 드래그 중 현재 선택된 타일은 테두리, 밝기, 확대 효과 등으로 명확하게 표시한다.
- 서로 다른 두 타일을 선택했을 때는 이모지를 잠시 확인할 수 있도록 짧은 피드백 시간을 제공한다.
- 브라우저의 기본 텍스트 선택과 모바일 페이지 스크롤이 게임 조작을 방해하지 않도록 보드에 적절한 `user-select: none`과 `touch-action`을 적용한다.
- 오답 피드백 또는 사라지는 애니메이션 중에는 추가 입력을 잠시 막아 상태가 꼬이지 않게 한다.

## 6. 화면 구성

첫 화면에서 바로 게임을 시작할 수 있도록 구성한다. 화면에는 다음 요소를 포함한다.

- 게임 제목: `푸드 이모지 짝찾기`
- 게임 설명: “같은 음식 이모지를 찾아 짝을 맞혀보세요.”
- 현재 점수: `점수: 0`
- 맞힌 쌍 수: `맞힌 쌍: 0 / 24`
- 시도 횟수: `시도: 0`
- 8행 6열 게임 보드
- `다시 시작` 버튼
- 게임 클리어 시 최종 점수와 시도 횟수를 보여주는 결과 영역

## 7. 반응형 디자인

- 데스크톱과 모바일에서 모두 사용할 수 있도록 반응형 레이아웃으로 만든다.
- 모바일 화면에서는 게임 보드를 화면 중앙에 배치하고 가로 스크롤이 생기지 않게 한다.
- 타일 크기는 화면 너비에 맞춰 조절하되, 음식 이모지가 읽히고 손가락으로 누르기 충분한 터치 영역을 유지한다.
- 보드의 8행 6열 구조가 어떤 화면에서도 흐트러지지 않도록 CSS Grid를 사용한다.
- 타일 크기 변화로 이모지나 선택 표시가 주변 타일과 겹치지 않게 한다.
- 음식의 느낌이 살아나도록 밝고 경쾌한 색상을 사용하되, 글자와 배경의 대비를 충분히 확보한다.

## 8. 시각 상태와 애니메이션

- 뒤집히지 않은 타일은 음식 이모지가 보이지 않는 카드 또는 패널 상태로 표시한다.
- 선택한 타일은 뒤집힘, 테두리 강조, 그림자 변화 등으로 구분한다.
- 정답 쌍은 짧은 성공 애니메이션 후 자연스럽게 사라지게 한다.
- 오답 쌍은 짧은 흔들림 또는 강조 효과 후 다시 뒤집힌 상태로 되돌린다.
- 게임 클리어 시 축하 메시지와 함께 보드가 완료되었음을 분명히 보여준다.
- `prefers-reduced-motion`을 지원해 모션 감소를 선호하는 사용자에게는 애니메이션을 줄이거나 생략한다.

## 9. JavaScript 상태와 기능

다음 게임 상태를 JavaScript에서 명확하게 관리한다.

- 음식 이모지 배열
- 무작위로 섞인 48개 타일 데이터
- 각 타일의 고유 ID와 음식 이모지 값
- 현재 선택된 타일 목록
- 맞힌 타일 목록 또는 제거 상태
- 점수
- 맞힌 쌍 수
- 시도 횟수
- 입력 잠금 여부
- 게임 클리어 여부

다음 기능을 함수 단위로 분리해 구현한다.

- 음식 이모지 24쌍 생성
- 배열 무작위 섞기
- 8행 6열 보드 렌더링
- 타일 선택 및 선택 상태 업데이트
- 두 타일의 음식 이모지 비교
- 정답 쌍 제거
- 오답 상태 복구
- 점수와 시도 횟수 갱신
- 모든 타일 제거 여부 확인
- 게임 재시작

## 10. 게임 클리어와 다시 시작

- 맞힌 쌍 수가 24가 되거나 남은 타일이 0개가 되면 게임 클리어로 판정한다.
- 클리어 화면에는 `게임 클리어!`, 최종 점수, 총 시도 횟수를 표시한다.
- 클리어 후에는 보드 입력을 막고 `다시 시작` 버튼을 제공한다.
- `다시 시작` 버튼을 누르면 점수, 시도 횟수, 선택 상태, 제거 상태를 모두 초기화한다.
- 새로운 24쌍을 생성하고 다시 섞어 새 게임을 시작한다.
- 진행 중인 오답 처리나 애니메이션이 있다면 재시작 시 타이머와 입력 잠금도 정리한다.

## 11. 접근성 및 품질 기준

- 타일은 가능하면 버튼 요소로 구현하거나 키보드로 접근할 수 있도록 한다.
- 게임 보드와 타일에 의미 있는 `aria-label`을 제공한다.
- 선택 상태와 맞힌 상태를 색상만으로 전달하지 말고 테두리, 모양, 텍스트 상태 등으로도 구분한다.
- 충분한 색상 대비와 명확한 포커스 표시를 제공한다.
- 브라우저 콘솔에 오류가 없어야 한다.
- `index.html`을 브라우저에서 직접 열어도 별도 설치나 서버 없이 실행되어야 한다.

## 12. 테스트 항목

완성 후 다음 항목을 직접 확인한다.

- 처음 실행했을 때 8행 6열, 총 48개의 타일이 표시되는가
- 모든 음식 이모지가 짝수 개로 배치되는가
- 데스크톱에서 마우스 클릭 또는 드래그로 두 타일을 선택할 수 있는가
- 모바일 또는 모바일 에뮬레이션에서 손가락 터치와 드래그가 동작하는가
- 같은 음식 이모지를 선택하면 두 타일이 사라지는가
- 다른 음식 이모지를 선택하면 잠시 피드백 후 다시 선택 가능한 상태가 되는가
- 정답 점수와 시도 횟수가 정확히 갱신되는가
- 모든 타일을 맞히면 게임 클리어 화면이 표시되는가
- 다시 시작하면 새 배치와 초기 점수로 돌아가는가
- 데스크톱과 모바일 화면에서 보드가 잘리지 않고 타일이 겹치지 않는가

## 13. 산출물

다음 파일을 `quiz02` 폴더에 작성한다.

- `index.html`: 게임 화면 구조, 타일 요소, 점수와 결과 영역
- `style.css`: 반응형 레이아웃, 카드 뒤집기, 선택·정답·오답 상태, 애니메이션
- `script.js`: 이모지 쌍 생성, 랜덤 배치, 클릭·드래그·터치 처리, 정답 비교, 점수 계산, 클리어 판정, 재시작

최종 결과는 사용자가 `index.html`을 직접 열기만 해도 즉시 실행되는 완성된 웹게임이어야 한다.
